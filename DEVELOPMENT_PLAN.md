# Подробный план разработки сайта BizonVR

План объединяет требования из **tech.md**, доработки из **upgrade.md** и текущее состояние проекта.

---

## 1. Текущее состояние проекта

### Реализовано
- **Django-проект:** `config` + приложение `catalog`
- **Модели:** `Category`, `Product`, `ProductCharacteristic` (категории: VR оборудование, аттракционы, трейдинг)
- **Каталог:** список товаров с фильтром по категории, сортировкой, пагинацией; детальная страница товара
- **Корзина:** хранение в сессии, модальное окно (Alpine.js), HTMX-фрагмент `cart_partial`
- **Верстка:** Tailwind CSS, Alpine.js, HTMX, Lucide-иконки, базовая страница и футер

### Не реализовано (из tech.md и upgrade.md)
- Выпадающее меню «Каталог» с разделами
- Пользователи и авторизация по номеру телефона + SMS
- Реферальная система, баланс, история заказов
- Оформление заказа (форма, доставка)
- Платежи (NowPayments)
- Поиск по сайту
- Docker, Nginx, PostgreSQL (сейчас, вероятно, SQLite)

### Фаза 2: Аккаунт по номеру телефона и SMS (upgrade.md п.3) ✅

**Цель:** регистрация/вход по номеру телефона с подтверждением по SMS.

| № | Задача | Описание | Зависимости |
|---|--------|----------|-------------|
| 2.1 | Модель пользователя | Кастомная модель пользователя (или расширение через Profile): обязательное поле «телефон», без обязательного username/email. Решение: `AbstractUser` с `USERNAME_FIELD = 'phone'` или `AbstractBaseUser` + свой UserManager. | Фаза 0 |
| 2.2 | SMS-провайдер | Выбор провайдера (Twilio, SMS.ru, SMSC и т.п.), обёртка в сервис: `send_sms(phone, code)`. Коды хранить во временном хранилище (Redis или БД) с TTL 5–10 мин. | 2.1 |
| 2.3 | Отправка кода | Endpoint: ввод номера телефона → генерация кода → отправка SMS → ответ «Код отправлен». Ограничение: не чаще 1 раз в N секунд с одного IP/номера. | 2.2 |
| 2.4 | Проверка кода и вход/регистрация | Endpoint: телефон + код. Если код верный — создать пользователя (если нет) и войти (session/login). Использовать `django.contrib.auth.login`. | 2.3 |
| 2.5 | Формы и шаблоны | Страницы/модалки: «Ввести телефон» → «Ввести код» → редирект в личный кабинет или на главную. Сообщения об ошибках (неверный код, истёк код). | 2.4 |
| 2.6 | Выход и отображение в шапке | Кнопка «Выйти», в шапке для авторизованных — «Личный кабинет» вместо «Войти». | 2.5 |

**Результат:** пользователь может зайти/зарегистрироваться только по номеру телефона с подтверждением по SMS.

| 3.2 | Модель заказа | `Order`: пользователь (nullable для гостей), статус, сумма, контакты, доставка, дата. `OrderItem`: заказ, товар, количество, цена. Связь корзины с заказом при оформлении. | Фаза 0 (orders) |
| 3.3 | История заказов | Страница «Мои заказы»: список заказов с деталями (товары, статус, сумма). Фильтр по статусу при необходимости. | 3.2, 2.6 |
| 3.4 | Баланс в ЛК | Отображение текущего баланса, при желании — таблица последних операций. Пополнение — в Фазе 5 (платежи). | 3.1 |
| 3.5 | Реферальная модель | Модель `Referral`: кто пригласил (user), кого пригласил (referred_user), код/ссылка. У пользователя поле `referrer` (ForeignKey, nullable) или отдельная таблица. | 2.1 |

| 3.7 | Страница «Рефералы» в ЛК | Список приглашённых, заработанные бонусы, реферальная ссылка для копирования. | 3.6 |

## 3. Зависимости между фазами

```
Фаза 0 (инфра) ──┬──► Фаза 1 (меню каталога)
                 ├──► Фаза 2 (телефон + SMS)
                 └──► Фаза 3 (ЛК, заказы, рефералы) ──► Фаза 4 (оформление заказа) ──► Фаза 5 (NowPayments)
                                                       Фаза 6 (поиск, безопасность, деплой)
```

- **Фаза 1** можно делать параллельно с Фазой 2.
- **Фаза 3** зависит от Фазы 2 (пользователь и ЛК).
- **Фаза 4** зависит от моделей заказа (Фаза 3) и корзины.
- **Фаза 5** зависит от заказа и (при пополнении баланса) от модели баланса.
- **Фаза 6** можно частично вести по ходу (поиск, безопасность) и завершить перед деплоем.

## 4. Рекомендуемый порядок работ

1. **Фаза 0** — приложения, .env, БД (и при необходимости Docker).
2. **Фаза 1** — выпадающее меню «Каталог» с разделами из upgrade.md.
3. **Фаза 2** — пользователь по телефону + SMS (вход/регистрация).
4. **Фаза 3** — модели заказа, баланса, рефералов; страницы ЛК: заказы, баланс, рефералы.
5. **Фаза 4** — оформление заказа из корзины, форма, доставка.
6. **Фаза 5** — интеграция NowPayments (инвойс + webhook).
7. **Фаза 6** — поиск, безопасность, локализация, деплой.

## 6. Риски и допущения

- **SMS:** нужен контракт с провайдером и бюджет на SMS; для разработки — заглушка или тестовый режим.
- **NowPayments:** нужен аккаунт и API-ключи; в тесте использовать sandbox, если есть.
- **Реферальные бонусы:** точные правила (процент, лимиты) нужно зафиксировать отдельно и реализовать в 3.6.
- **Гостевые заказы:** в плане учтены (nullable user у заказа); при желании можно ограничить оформление только для авторизованных.

План можно использовать как чек-лист: отмечать выполненные пункты и при необходимости дробить задачи на более мелкие в трекере или в коде.
