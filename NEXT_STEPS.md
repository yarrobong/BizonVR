## Фаза 4: Оформление заказа (приоритет)

### Шаг 4.1 — Добавление товара в корзину (сессия)

**Цель:** при нажатии «Добавить в корзину» сохранять товар в `request.session['cart_items']` и обновлять модалку/счётчик.

1. **Формат корзины в сессии**  
   Использовать список словарей, например:
   ```python
   cart_items = [
       {
           'product_id': 1,
           'name': 'Название товара',
           'price': 1000,
           'quantity': 2,
           'image_url': '/media/products/1.png',  # или ''
           'subtotal': 2000,
       }
   ]
   ```
   Ключ сессии: `cart_items` (уже используется в `cart_partial`).

2. **View «добавить в корзину»** (приложение `catalog`):
   - URL: например `POST /catalog/cart/add/<int:product_id>/`.
   - Логика:
     - Получить `Product` по `product_id`, проверить `is_active=True`.
     - Прочитать `request.session.get('cart_items', [])`.
     - Если товар уже есть — увеличить `quantity`, пересчитать `subtotal`.
     - Если нет — добавить новую позицию (name, price, quantity, image_url, subtotal).
     - Сохранить список в `request.session['cart_items']` и вызвать `request.session.modified = True` (или использовать `SESSION_SAVE_EVERY_REQUEST`).
   - Ответ:
     - Для обычного запроса: редирект на `next` или на страницу товара.
     - Для HTMX (заголовок `HX-Request`): вернуть JSON `{ "ok": true, "cart_count": N }` или фрагмент HTML с обновлённой корзиной и числом позиций.

3. **Обновить шаблон карточки товара** (`templates/catalog/product_detail.html`):
   - Кнопку «Добавить в корзину» сделать формой с `method="post"` и `action="{% url 'catalog:add_to_cart' product.pk %}"` или отправить POST через HTMX.
   - После успешного добавления: вызвать `$dispatch('open-cart')` и обновить счётчик в шапке (например через `hx-get` корзины и подстановку в `#cart-count`).

4. **Опционально — view «изменить количество / удалить из корзины»**:
   - `POST /catalog/cart/update/` с `product_id` и `quantity` (0 = удалить).
   - Обновлять `cart_items` в сессии и возвращать фрагмент корзины для HTMX.

**Результат:** товары попадают в корзину, модалка и счётчик отображают актуальные данные.

---

### Шаг 4.2 — Счётчик корзины в шапке

**Цель:** в `base.html` показывать реальное количество позиций (или сумму товаров) из сессии.

1. **Context processor** (уже есть `catalog.context_processors` или добавить в него):
   - Вычислять `cart_items = request.session.get('cart_items', [])`.
   - Считать `cart_count` = число позиций (или сумма `quantity` по всем позициям — как решите).
   - Добавлять в контекст: `cart_count`, при необходимости `cart_total`.

2. **В `templates/base.html`**:
   - Заменить захардкоженный `0` в блоке с корзиной на `{{ cart_count|default:0 }}`.
   - При обновлении корзины через HTMX после добавления товара — обновлять `#cart-count` (например, через `hx-swap-oob` или отдельный маленький endpoint, который возвращает только число, и подставлять его в шапку).

**Результат:** в шапке отображается актуальное количество товаров в корзине.

### Шаг 4.3 — Модель заказа (уточнение полей)

**Цель:** убедиться, что в заказе есть все поля для оформления и доставки.

В `orders/models.Order` уже есть: `phone`, `email`, `first_name`, `last_name`, `address`, `comment`. При необходимости добавьте:

- **Способ доставки:** например `delivery_type` (CharField с choices: «курьер», «самовывоз», «почта») — по желанию.
- Миграции: `python manage.py makemigrations orders` и `migrate`.

**Результат:** модель заказа готова к форме оформления.

### Шаг 4.4 — Страница оформления заказа (checkout)

**Цель:** отдельная страница (или модалка) с формой контактов и доставки, по сабмиту — создание заказа из корзины.

1. **View checkout** (в приложении `orders` или `catalog` — логичнее `orders`):
   - `GET`: показать форму (контакты, адрес, комментарий, способ доставки если есть).
   - Для авторизованных: подставлять в форму `phone`, `first_name`, `last_name`, `email` из профиля/пользователя.
   - `POST`:
     - Валидация формы.
     - Проверить, что в сессии есть `cart_items` и они не пустые; при необходимости проверить актуальность цен по БД.
     - Создать `Order`: user=request.user (или None для гостя), статус `STATUS_NEW`, контакты и адрес из формы, `total` = сумма по корзине.
     - Создать `OrderItem` для каждой позиции корзины (product_id, quantity, price на момент заказа).
     - Очистить `request.session['cart_items']`.
     - Редирект на страницу «Заказ оформлен» или на детальную страницу заказа `orders:order_detail` (для авторизованных) или на страницу с номером заказа для гостя.

2. **Форма** (Django Form):
   - Поля: телефон, имя, фамилия, email (для гостя обязателен), адрес доставки, комментарий, способ доставки (если есть).
   - Валидация: телефон обязателен, при необходимости — маска или проверка формата.

3. **Шаблон** `templates/orders/checkout.html`:
   - Вывести список товаров из корзины (из сессии или переданных в контексте) и итог.
   - Форму с кнопкой «Оформить заказ».
   - Сообщения об ошибках (пустая корзина, неверные данные).

4. **URL:** например `path('checkout/', views.checkout_view, name='checkout')` в `orders.urls`.

**Результат:** пользователь и гость могут оформить заказ; заказ создаётся, корзина очищается.

### Шаг 4.5 — Ссылка «Оформить заказ» в модалке корзины

**Цель:** кнопка в модалке корзины ведёт на страницу checkout.

В `templates/base.html` заменить:

```html
<a href="#">Оформить заказ</a>
```

на:

```html
<a href="{% url 'orders:checkout' %}">Оформить заказ</a>
```

При пустой корзине можно показывать кнопку неактивной или не показывать.

**Результат:** из корзины можно перейти к оформлению заказа.

### Шаг 4.6 — Оплата балансом (опционально)

**Цель:** если у пользователя достаточно баланса — списать с баланса и перевести заказ в «Оплачен» без перехода к NowPayments.

1. В форме checkout или на странице «Заказ создан» добавить вариант: «Оплатить с баланса» (показывать только если `user.is_authenticated` и баланс >= сумма заказа).
2. Отдельный endpoint: «списать с баланса за заказ»:
   - Проверить заказ (user, статус New), сумму и баланс.
   - Создать запись в истории баланса (списание), обновить профиль и статус заказа на «Оплачен».
3. После успешной оплаты балансом — редирект в ЛК или на страницу заказа.

**Результат:** авторизованные пользователи могут оплачивать заказ с личного счёта.

## Фаза 5: Платежи NowPayments (довести до конца)

Интеграция уже есть: создание платежа, webhook, страница ожидания. Остаётся связать с checkout.

### Шаг 5.1 — Переход «Оплатить криптой» после создания заказа

**Цель:** после оформления заказа дать пользователю кнопку «Оплатить криптой», ведущую на создание платежа NowPayments.

1. На странице «Заказ оформлен» / детальной странице заказа (`order_detail`) для заказов со статусом `New` показывать кнопку:
   - «Оплатить криптой» → переход на `payments:create_payment` с `order_id`.
2. В `orders` (шаблон детали заказа) добавить ссылку:
   ```html
   <a href="{% url 'payments:create_payment' order.pk %}">Оплатить криптой</a>
   ```
   Показывать только если `order.status == 'new'` и заказ принадлежит текущему пользователю.

**Результат:** полный цикл: корзина → checkout → заказ → оплата NowPayments.

### Шаг 5.2 — Переменные окружения и .env

Убедиться, что в `.env` и `config.settings` заданы:

- `NOWPAYMENTS_API_KEY`
- `NOWPAYMENTS_IPN_SECRET`
- При необходимости `NOWPAYMENTS_API_BASE` (для sandbox) и `SITE_URL` для callback.

**Результат:** в продакшене платежи работают с реальным или тестовым API.

## Фаза 6: Доработки (по необходимости)

### Шаг 6.1 — Гостевой заказ

Сейчас в коде заказ может быть без пользователя (`user=null`). Нужно:

- Разрешить доступ к странице «Заказ оформлен» для гостя (например по токену в ссылке или по номеру заказа + телефон).
- Страница «Мои заказы» только для авторизованных; гостю показывать сообщение «Заказ № X оформлен, следите за статусом по ссылке из письма/SMS» (если решите отправлять уведомления).

### Шаг 6.2 — Поиск в футере

В `base.html` в футере есть поле «Поиск» без `action`. Привязать к тому же `catalog:product_list` с параметром `q` (как в шапке).

### Шаг 6.3 — Безопасность и лимиты

- Ограничение частоты запросов на добавление в корзину / checkout (например через `django-ratelimit` или middleware).
- Проверка CSRF на всех формах (уже должно быть).
- В продакшене: HTTPS, корректные `ALLOWED_HOSTS`, `SECRET_KEY` из env.

### Шаг 6.4 — Тесты

- Тест: добавление в корзину (сессия), счётчик.
- Тест: checkout создаёт заказ и очищает корзину.
- Тест: оплата балансом (если реализована) и переход на NowPayments (мок API).
