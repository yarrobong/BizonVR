# Git Workflow

## Что считать главным

- `main` — единственная главная ветка проекта.
- В `main` держим только рабочее состояние, которое хотя бы проходит `manage.py check` и базовые тесты.

## Какие ветки создавать дальше

- `feat/<кратко-что-делаем>` — новая функциональность.
- `fix/<кратко-что-чинится>` — исправление бага.
- `chore/<кратко-что-обслуживаем>` — техдолг, инфраструктура, Git, документация.
- `archive/<дата>-<описание>` — только для сохранения старого WIP, если его нельзя сразу удалить.

## Простой порядок работы

1. Перед началом обновите `main`: `git checkout main && git pull`.
2. Создайте отдельную ветку от `main`.
3. Делайте одну задачу в одной ветке.
4. Когда задача готова, прогоните минимум:
   `python manage.py check`
   `DJANGO_SETTINGS_MODULE=config.settings_test ... manage.py test orders payments accounts --noinput`
5. После слияния в `main` удаляйте рабочую ветку, если она больше не нужна.

## Чего больше не делать

- Не работать долго прямо в `main`.
- Не держать десятки одноразовых веток `claude/*` как активные.
- Не смешивать в одной ветке UI-эксперименты, миграции и несвязанные правки.
- Не оставлять незакоммиченный WIP без архива, если ветку нужно закрыть.

## Быстрое правило

Если сомневаетесь: обновили `main`, создали новую короткую ветку, сделали одну задачу, проверили, слили, удалили ветку.
