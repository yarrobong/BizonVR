# ТЗ: блоки визуального описания товара в карточке товара

## 1. Цель

Реализовать в карточке товара дополнительную секцию **“Подробное описание”**, состоящую из управляемых контент-блоков, которые менеджер сможет заполнять через Django admin без правки кода.

Основная задача:

* под основным описанием товара выводить красивые блоки;
* в каждом блоке можно задать:

  * заголовок,
  * текст,
  * изображение,
  * положение изображения: слева или справа;
* блоки можно сортировать;
* блоки должны аккуратно выглядеть на десктопе и мобилке;
* решение должно легко встраиваться в текущий Django-проект.

---

## 2. Формат MVP

На первом этапе реализовать только минимально нужный функционал.

### Поддерживаемые типы блоков:

1. **Текстовый блок**

   * заголовок
   * текст

2. **Блок “картинка + текст”**

   * заголовок
   * текст
   * изображение
   * положение изображения:

     * слева
     * справа

3. **Большое изображение**

   * изображение
   * необязательный заголовок
   * необязательная подпись

Этого достаточно, чтобы делать длинное красивое описание товара по аналогии с маркетплейсами.

---

## 3. Где выводить на сайте

В карточке товара новая секция должна выводиться **после стандартного описания / кратких характеристик**, но **до блока “Ещё товары”**.

Рекомендуемый порядок:

1. главный блок товара;
2. цена / покупка / доставка;
3. краткое описание;
4. **подробное визуальное описание товара**;
5. характеристики;
6. похожие / ещё товары;
7. футер.

---

## 4. Что должно быть в админке

Для каждого товара в Django admin должна быть возможность добавить несколько блоков подробного описания.

### Для каждого блока должны быть поля:

* **Товар**
* **Тип блока**
* **Заголовок**
* **Текст**
* **Изображение**
* **Положение изображения**

  * left
  * right
* **Подпись к изображению** (необязательно)
* **Порядок сортировки**
* **Активен / неактивен**

### Поведение:

* менеджер может создать любое количество блоков;
* менеджер может менять порядок отображения;
* менеджер может временно скрыть блок без удаления;
* блоки отображаются на странице товара строго по сортировке.

---

## 5. Требования к UX в админке

Нужно сделать админку максимально простой, чтобы менеджер не путался.

### В админке должно быть:

* inline-редактирование блоков внутри товара;
* понятные названия полей;
* превью загруженного изображения;
* сортировка по числу `sort_order`;
* подсказки у полей.

### Пояснения для менеджера:

* “Заголовок блока” — крупный текст секции;
* “Текст блока” — описание секции;
* “Положение изображения” — слева или справа относительно текста;
* “Порядок” — чем меньше число, тем выше блок на странице.

---

## 6. Архитектура данных

## Модель товара

Используется существующая модель `Product`.

## Новая модель

Нужна отдельная модель, например:

`ProductContentBlock`

### Поля модели:

* `product` — ForeignKey на товар
* `block_type` — тип блока
* `title` — заголовок
* `text` — текст
* `image` — картинка
* `image_position` — left/right
* `caption` — подпись к изображению
* `sort_order` — порядок
* `is_active` — активность
* `created_at`
* `updated_at`

### Значения `block_type`:

* `text`
* `image_text`
* `full_image`

---

## 7. Логика отображения на фронтенде

## Блок `text`

Показывает:

* заголовок
* текст

## Блок `image_text`

Показывает:

* сетку из 2 колонок на десктопе:

  * либо изображение слева, текст справа;
  * либо текст слева, изображение справа;
* на мобилке всегда в одну колонку:

  * сначала изображение,
  * потом текст.

## Блок `full_image`

Показывает:

* большую картинку на ширину контентной области;
* ниже необязательную подпись.

---

## 8. Требования к внешнему виду

Нельзя просто “вставить картинку и текст”. Нужно сделать визуально аккуратно и в стиле текущего сайта BizonVR.

### Визуальные требования:

* единый контейнер по ширине сайта;
* крупные отступы между блоками;
* скруглённые углы;
* фон и бордеры в стиле текущей тёмной темы;
* изображения без искажений;
* заголовки визуально сильнее обычного текста;
* текст должен быть легко читаем;
* блоки не должны выглядеть как “сырой HTML из CMS”.

### Рекомендуемый стиль:

* карточечные секции;
* вертикальный ритм 24–48 px;
* изображение и текст выровнены по центру по высоте;
* внутри длинных текстов нормальная ширина строки;
* на мобилке хороший воздух между элементами.

---

## 9. Адаптивность

### Десктоп

* блок `image_text` — 2 колонки;
* соотношение примерно 50/50 или 55/45;
* между колонками комфортный gap.

### Планшет

* допускается переход в 1 колонку;
* или сохранение 2 колонок при достаточной ширине.

### Мобилка

* все блоки в 1 колонку;
* картинка сверху;
* текст снизу;
* шрифты и отступы уменьшены, но читаемость сохранена.

---

## 10. Требования к изображениям

### Нужно реализовать:

* загрузку изображений через админку;
* хранение в media;
* автоматическое корректное отображение по размеру;
* `object-fit: cover` или `contain` в зависимости от дизайна;
* lazy loading для фронтенда;
* обязательный `alt`.

### Желательно:

* поддержка WebP;
* ограничение слишком больших файлов;
* генерация уменьшенных версий позже как отдельная задача.

---

## 11. Интеграция в Django

## Backend

Нужно:

* создать модель `ProductContentBlock`;
* сделать миграцию;
* зарегистрировать модель в Django admin;
* добавить inline-блоки в админку товара;
* обеспечить сортировку;
* на странице товара передавать блоки в шаблон.

## Frontend

Нужно:

* создать отдельный partial-шаблон, например:

  * `catalog/partials/product_content_blocks.html`
* подключить его в карточку товара;
* сделать отдельный CSS-файл или модуль секции;
* реализовать шаблоны рендера по `block_type`.

---

## 12. Структура шаблонов

Рекомендуется не смешивать всё в один файл.

### Предлагаемая структура:

* `product_detail.html` — основная карточка товара
* `partials/product_content_blocks.html` — цикл по блокам
* `partials/content_blocks/text.html`
* `partials/content_blocks/image_text.html`
* `partials/content_blocks/full_image.html`

Так будет проще поддерживать и расширять.

---

## 13. Что нельзя делать

Чтобы потом не было проблем, сразу зафиксировать ограничения.

### Не использовать:

* одно большое HTML-поле для всей секции;
* ручную вставку в description сложной верстки;
* inline-стили из админки;
* необработанный HTML от менеджера;
* хаотичную загрузку изображений без структуры.

### Почему:

* сложно редактировать;
* легко сломать вёрстку;
* неудобно поддерживать;
* плохо адаптируется под мобильные.

---

## 14. Приёмочные критерии

Задача считается выполненной, если:

1. В админке товара можно добавить несколько блоков подробного описания.
2. Для блока “картинка + текст” можно выбрать:

   * картинка слева,
   * картинка справа.
3. Блоки можно сортировать.
4. Блок можно отключить без удаления.
5. На странице товара блоки выводятся в правильном порядке.
6. На десктопе блоки выглядят аккуратно и согласованно с дизайном сайта.
7. На мобильных блоки не ломаются и читаются удобно.
8. Изображения и текст не выходят за контейнер.
9. Внедрение не ломает текущую карточку товара.
10. Менеджер может без программиста заполнить секцию у нового товара.

---

## 15. Этапы реализации

## Этап 1. Backend

* создать модель `ProductContentBlock`;
* сделать миграцию;
* добавить регистрацию в admin;
* добавить inline к товару.

## Этап 2. Шаблоны

* создать partial для секции;
* реализовать шаблоны трёх типов блоков;
* встроить вывод в карточку товара.

## Этап 3. CSS / UI

* сделать стили секции;
* сделать адаптив;
* привести внешний вид к стилю BizonVR.

## Этап 4. Тестирование

* проверить 0 блоков;
* проверить 1 блок;
* проверить 5–10 блоков;
* проверить мобильную версию;
* проверить длинные тексты;
* проверить большие и вертикальные изображения.

---

## 16. Что можно добавить на втором этапе

После MVP можно расширить:

* галерея из нескольких фото;
* видео-блок;
* блок преимуществ в карточках;
* блок “Комплектация”;
* drag-and-drop сортировка в админке;
* предпросмотр блока в админке;
* отдельные изображения для мобилки;
* WYSIWYG только для форматирования текста внутри блока;
* шаблоны секций для быстрого копирования между товарами.

---

## 17. Рекомендуемое решение

Для твоей задачи оптимальный вариант такой:

### Делать сейчас:

* `text`
* `image_text`
* `full_image`
* `sort_order`
* `is_active`
* `image_position`

### Не делать сейчас:

* сложный визуальный конструктор;
* свободный HTML;
* перегруженную CMS;
* десятки типов блоков.

Это даст быстрый, аккуратный и понятный результат без лишней сложности.

---

## 18. Короткая формулировка для разработчика

Нужно добавить в карточку товара управляемую секцию “Подробное описание”, состоящую из контент-блоков. Блоки редактируются через Django admin. Минимально поддержать 3 типа: текст, картинка+текст, большое изображение. Для блока картинка+текст менеджер должен выбирать положение изображения слева или справа. Блоки должны сортироваться, отключаться и корректно отображаться на десктопе и мобильных. Вся секция должна быть визуально оформлена в стиле текущего сайта и подключаться в карточку товара без ломки существующей логики.
