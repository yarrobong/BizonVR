# Описание работ, схемы и эскизы по веб-проекту BizonVR

## 1. Краткое описание веб-проекта

BizonVR — это веб-проект в формате интернет-магазина VR-оборудования, аксессуаров и VR-аттракционов. Сайт ориентирован на публикацию каталога, приём заявок и заказов, сопровождение онлайн-оплаты, работу с личным кабинетом пользователя и внутреннюю обработку заказов менеджерами.

Проект реализован как серверное Django-приложение с единым runtime-контуром. Публичная часть сайта, оформление заказов, платёжный сценарий, административная панель и внутренний менеджерский портал работают в рамках одной кодовой базы и одной PostgreSQL-базы данных.

## 2. Цель разработки

Целью разработки являлось создание рабочего веб-сервиса для продажи VR-товаров и сопутствующих услуг с полным циклом обработки обращения:

- публикация каталога товаров и услуг;
- сбор корзины для гостя и авторизованного пользователя;
- оформление заказа с контактными и юридически значимыми данными;
- сопровождение оплаты по СБП, банковской карте или через менеджера;
- предоставление пользователю личного кабинета;
- предоставление сотрудникам инструментов для сопровождения заказов, логистики, финансов и документов.

## 3. Описание выполненных работ

В рамках проекта были реализованы и собраны в единое решение следующие работы:

- разработана публичная витрина интернет-магазина с главной страницей, каталогом, карточками товаров и страницами услуг;
- реализована корзина с поддержкой гостевого и авторизованного режима;
- реализовано избранное и механизм шаринга корзины;
- реализован checkout-процесс с валидацией остатков, контактных данных, адреса, получателя и обязательных согласий;
- реализован модуль заказов с историей, статусами, составом заказа и защищённым доступом к гостевым заказам;
- реализован модуль платежей и обработка статусов оплаты через webhook;
- реализована авторизация по SMS-коду и по email-коду, а также профиль пользователя с сохранёнными адресами;
- реализованы формы обращений, обратного звонка и сервисных заявок;
- настроена административная часть для сопровождения каталога, заказов, оплат и контента;
- реализован внутренний менеджерский портал для работы с логистикой, резервами, договорами, закупками, финансами и клиентскими сделками;
- подготовлен production-деплой на связке Gunicorn + systemd + Nginx;
- добавлены автоматизированные тесты для ключевых сценариев каталога, аккаунтов, заказов, оплат и manager portal.

## 5. Основные модули проекта

### `catalog`

Основной модуль витрины интернет-магазина. Отвечает за разделы каталога, категории, товары, варианты товаров, изображения, характеристики, наборы товаров, остатки по точкам выдачи, корзину, избранное, услуги и входящие обращения.

### `orders`

Модуль оформления и сопровождения заказов. Отвечает за checkout, промокоды, состав заказа, статусы заказа, историю заказов и связанные пользовательские сценарии после оформления.

### `payments`

Модуль создания платёжных сущностей и обработки результата оплаты. Поддерживает сценарий открытия страницы оплаты для заказа и webhook-обработку статуса завершённого платежа.

### `accounts`

Модуль аутентификации и профиля. Поддерживает вход по SMS-коду, вход по email-коду, профиль клиента, баланс, сохранённые адреса и подтверждение контактных данных.

### `manager_portal`

Внутренний бизнес-модуль для сотрудников. Содержит инструменты для работы со сделками, заказами, резервами, отгрузками, закупками, грузами, финансами, договорами и импортом legacy-данных.

### `config`

Корневой модуль конфигурации проекта. Содержит настройки Django, маршрутизацию, базовые страницы, sitemap, legal pages, медиа-обработку и общий каркас проекта.

## 6. База данных

Проект использует одну основную базу данных PostgreSQL. Отдельные runtime-базы данных в рабочем контуре не применяются. Это соответствует архитектурному принципу single-db.

Ключевые группы сущностей:

- каталог: `CatalogSection`, `Category`, `Product`, `ProductVariant`, `ProductImage`, `ProductCharacteristic`, `ProductBundle`;
- наличие и география: `City`, `PickupPoint`, `ProductStock`;
- корзина и избранное: `CartItem`, `CartShare`, `Favorite`;
- заказы: `Order`, `OrderItem`, `PromoCode`, `PurchaseRequest`;
- оплаты: `Payment`;
- аккаунты: `Profile`, `SavedAddress`, `BalanceTransaction`, `PhoneVerificationCode`, `EmailVerificationCode`, `EmailLoginCode`;
- внутренний контур: сделки, склады, резервы, закупки, грузы, финансы, договоры и импортные сущности `manager_portal`.

### Упрощённая схема данных

```text
CatalogSection -> Category -> Product -> ProductVariant
                                 |            |
                                 |            -> ProductStock -> PickupPoint -> City
                                 |
                                 -> ProductImage
                                 -> ProductCharacteristic

User -> Profile
User -> SavedAddress
User -> CartItem
User -> Favorite

Order -> OrderItem
Order -> Payment
Order -> PromoCode
```

## 7. Интерфейс пользователя

Пользовательский интерфейс проекта построен по модели серверного рендеринга. Основной layout находится в `templates/base.html`. Для стилизации используется Tailwind CSS, а для локальной интерактивности применяются HTMX и Alpine.js.

В интерфейсе реализованы:

- главная страница с промо-блоками и навигацией;
- каталог с фильтрацией, поиском, сортировкой и карточками товаров;
- карточка товара с галереей, вариантами, остатками и рекомендательными блоками;
- корзина и one-click сценарии;
- checkout-форма с доставкой, контактами, получателем и юридическими согласиями;
- личный кабинет с профилем, адресами, историей заказов и настройками;
- адаптация под мобильные устройства и desktop-сценарии.

## 8. Административная часть

Административная часть проекта состоит из двух уровней.

### Django Admin

Используется для сопровождения справочников и операционных данных:

- каталог и карточки товаров;
- изображения, характеристики и фильтры;
- города, точки выдачи и остатки;
- заказы, позиции заказов и промокоды;
- платежи;
- профили пользователей и коды подтверждения;
- заявки, обращения и сервисные формы.

### Manager Portal

Отдельный внутренний интерфейс по маршруту `/manager/`, предназначенный для сотрудников и менеджеров. Включает:

- управление клиентами и сделками;
- обработку заказов;
- логистику и отгрузки;
- складской учёт и резервы;
- закупки и грузы;
- финансовые сущности и отчёты;
- договорные документы и шаблоны;
- импорт данных из legacy-источников в основную PostgreSQL-базу.

## 10. Деплой

Развёртывание проекта предусмотрено на Linux-сервере с использованием:

- `venv` для Python-окружения;
- Gunicorn как WSGI-сервера;
- systemd для управления сервисом;
- Nginx как reverse proxy и точка входа HTTPS;
- PostgreSQL как единственной рабочей базы данных;
- `collectstatic` для подготовки статических файлов.

Типовая последовательность обновления проекта:

```bash
.venv/bin/pip install -r requirements.txt
npm install
npm run build:css
.venv/bin/python scripts/check_single_db_contract.py
.venv/bin/python manage.py migrate
.venv/bin/python manage.py collectstatic --noinput
sudo systemctl restart bizonvr
sudo systemctl reload nginx
```

- карточка товара, варианты и блоки контента;
- корзина, избранное и шаринг корзины;

- валидация остатков и юридических согласий;
- создание заказа и защита гостевого доступа;
- доступ к оплате и ограничения безопасности;
- авторизация, восстановление доступа, SMS/email-коды;

Основные команды проверки:

```bash

```

## 12. Итоговый результат

В результате разработки создан полнофункциональный веб-проект BizonVR, который обеспечивает:

- публикацию и сопровождение каталога VR-товаров и услуг;
- оформление заказов с оплатой и контролем остатков;
- работу личного кабинета и аутентификацию по коду;
- управление операционной деятельностью через административную панель и manager portal;
- централизованное хранение данных в PostgreSQL;
- готовность к production-развёртыванию и сопровождению.

Итоговое решение представляет собой единый e-commerce и back-office контур для онлайн-продаж, клиентского самообслуживания и внутренней работы команды магазина.
