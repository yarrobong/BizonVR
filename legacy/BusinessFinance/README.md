# Управленческий учёт (Business Finance)

Streamlit-приложение для учёта сделок, расходов и расчётов с партнёром. База данных — **PostgreSQL**.

## Требования

- Python 3.10+
- PostgreSQL 14+ (локально или в Docker)

## Установка и запуск

### Запуск полностью через Docker (рекомендуется)

Всё поднимается одной командой: PostgreSQL + приложение.

```bash
docker compose up -d
```

Приложение будет доступно по адресу **http://localhost:8501**. Логин по умолчанию: `admin`, пароль задаётся переменной `ADMIN_INITIAL_PASSWORD` (по умолчанию `admin`). Опционально создайте `.env` и задайте `ADMIN_INITIAL_PASSWORD`, `COOKIE_SECRET`.

Остановка: `docker compose down`.

---

### Локальный запуск (Python + PostgreSQL)

1. Клонируйте репозиторий и перейдите в каталог проекта.

2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. Запустите PostgreSQL (только БД; приложение запускаете сами на шаге 5).

   **Вариант A — Docker (только Postgres):**

   ```bash
   docker compose up -d postgres
   ```

   Будет создана БД `finance`, пользователь `finance`, пароль `finance`. Postgres слушает порт **5433** (чтобы не конфликтовать с локальным PostgreSQL на 5432).

   **Вариант B — локальный PostgreSQL:**

   Создайте базу и пользователя, затем задайте `DATABASE_URL` в `.env` (см. ниже).

4. Настройте подключение к БД.

   Скопируйте `.env.example` в `.env` и при необходимости измените `DATABASE_URL`:

   ```bash
   cp .env.example .env
   ```

   - **Локальный PostgreSQL:** по умолчанию `postgresql://postgres:postgres@localhost:5432/postgres`. Укажите свой пароль пользователя `postgres`, если он другой.
   - **Docker:** укажите `postgresql://finance:finance@localhost:5433/finance` (порт 5433).

   Ошибка *role "finance" does not exist* — приложение подключается к локальному Postgres на 5432, а не к Docker. Запустите `docker compose up -d` и используйте в `DATABASE_URL` порт **5433** (Docker слушает именно его).

5. Запустите приложение:

   ```bash
   streamlit run app.py
   ```

   Откройте в браузере адрес, указанный в консоли (обычно http://localhost:8501).

## Авторизация и роли

- **Вход**: логин и пароль, проверка по БД (пароли хранятся в виде bcrypt-хешей).
- **Роли**:
  - **Админ** — полный доступ плюс раздел «Настройки»: типы сделок и доли партнёра, категории расходов (наши / партнёра), пользователи. Изменения применяются только к **новым** сделкам и расходам.
  - **Оператор** — ввод сделок, расходов, выплат; просмотр дашборда и архива.

При первом запуске создаётся пользователь **admin**. Пароль задаётся переменной `ADMIN_INITIAL_PASSWORD` в `.env` (по умолчанию `admin`). Рекомендуется сменить его в Настройки → Пользователи.

Сессия хранится в зашифрованном cookie: после входа вас не выкидывает при перезагрузке страницы. Срок жизни сессии задаётся `SESSION_EXPIRE_DAYS` в `.env` (по умолчанию 7 дней). Для шифрования cookie можно задать `COOKIE_SECRET` (в проде — обязательно).

## Структура проекта

- **`app.py`** — точка входа: авторизация, навигация, маршрутизация по страницам
- **`config.py`** — конфигурация (DATABASE_URL, константы)
- **`db.py`** — подключение к PostgreSQL, запросы, миграции и сиды
- **`logic.py`** — бизнес-логика (сделки, расходы, справочники, расчёты)
- **`auth.py`** — авторизация (verify_user, hash_password)
- **`styles.py`** — кастомные CSS-стили
- **`views/`** — UI-страницы:
  - `deal.py` — форма новой сделки
  - `deals.py` — список сделок и карточка сделки с расходами
  - `expenses.py` — операционные расходы (наши / партнёра)
  - `payouts.py` — фиксация выплат
  - `dashboard.py` — дашборд с расчётом месяца
  - `settings.py` — настройки (типы сделок, категории, пользователи)
  - `archive.py` — архив операций

## Структура БД (PostgreSQL)

- **users** — пользователи (логин, хеш пароля, роль)
- **deal_types** — типы сделок и доля партнёра (настраивается админом)
- **our_expense_categories**, **partner_expense_categories** — справочники категорий расходов
- **deals** — сделки (дата, договор, тип, выручка, закуп, расходы, бонус, маржа, доля партнёра)
- **expenses** — расходы: наши (`expense_side = 'ours'`) и партнёра (`expense_side = 'partner'`)
- **payouts** — выплаты партнёру

Таблицы и начальные данные создаются при первом запуске (`init_db`). Миграция с SQLite не предусмотрена; при переходе с SQLite данные нужно перенести вручную.
